# pull-remote-code

**触发时机：Agent 开始编码前（编码前置步骤）。**

用途：先把指定工作区内**所有 git 仓库**的最新远程代码同步到本地，再开展用户分派的工作；避免基于过期代码编码，减少无谓冲突。**纯通用：不写死任何仓库名、目录名或业务规范。**

## 1. 扫描范围（动态发现）

从 `-Root` 指定目录（默认取脚本目录向上 4 级）递归查找所有含 `.git` 的目录，即得到全部仓库；`node_modules` / `.pnpm` / `vendor` / `.venv` 内的一律忽略。与仓库数量、名称、层级无关。

## 2. 同步口径（安全快进）

对每个仓库：

1. `git fetch --all --prune`
2. 读取当前分支的 upstream
3. 比较 `HEAD...@{u}` 领先/落后数：
   - **落后 0** → 已最新，`UP_TO_DATE`
   - **仅落后、无本地领先**且工作区干净 → `git merge --ff-only` 快进，`FAST_FORWARD`
   - **工作区有未提交改动**（含暂存/未跟踪）→ **只 fetch 不合并**，标记 `DIRTY_SKIPPED`（不 stash、不 reset）
   - **本地领先或双向分叉** → `DIVERGED`，需人工处理
   - 未设置 upstream / 分离 HEAD → 对应标记，跳过

**硬性禁止**：不 `reset --hard`、不 `push --force`、不 `stash`、不丢弃任何本地改动。脏工作区绝不强拉。

## 3. 一键执行

```powershell
pwsh -File pull-all.ps1 -Root "<工作区根目录>"
```

省略 `-Root` 时默认取脚本目录向上 4 级；可用 `-IgnoreDir '<正则>'` 自定义要忽略的目录。

脚本输出逐仓状态表；**退出码 0 = 全部已同步**，`1` = 有仓库未完成（脏跳过 / 分叉 / 快进失败 / 无 upstream），`2` = 参数或路径错误。需先处置未完成的仓库再编码。

## 4. 执行后处理

| 脚本状态 | 处理 |
|---|---|
| `FAST_FORWARD` / `UP_TO_DATE` | 直接进入编码 |
| `DIRTY_SKIPPED` | 该仓有未提交改动，未拉取。先确认改动归属，再由人工提交/搁置后重跑，**不得自行 stash 覆盖** |
| `DIVERGED` / `FF_FAILED` | 需人工 rebase/merge，勿强行覆盖 |
| `NO_UPSTREAM` / `DETACHED_HEAD` | 先切回正常分支或设置 upstream，再重跑 |

- 同步后如依赖清单或数据结构有变化，按**该项目自身**的约定处理（本技能不预设任何项目特定步骤）。

## 5. 硬规则

- 只做拉取同步，不顺手重构、不改业务代码。
- 各仓库独立，各自同步、各自提交，互不混合。
- 脏工作区只报告不覆盖；不制造任何隐式暂存或强制覆盖。
- 同步是编码前置，完成后再开始用户分派的工作。
